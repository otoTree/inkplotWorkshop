## 1. 文档目的与事实口径

### 1.1 文档目的

本 PRD 用于回答四个问题：

- 当前产品实际上能为谁解决什么问题；
- 用户可以完成哪些端到端任务，关键业务规则是什么；
- 哪些能力已经形成可用闭环，哪些只是部分实现或代码骨架；
- 若继续产品化，下一阶段应优先补齐哪些发布门槛与产品缺口。

### 1.2 事实判定规则

- “已接入”：存在可访问页面或操作入口，且数据通过当前主数据层持久化。
- “部分接入”：存在页面、组件或接口，但入口、存储、配置或端到端闭环不完整。
- “代码骨架”：存在类型、迁移、算法或组件，但当前主路由与主数据映射未使用。
- “建议”：为形成完整 PRD 而提出的目标或改进，不代表当前代码已经实现。

### 1.3 事实来源优先级

以当前路由与组件、`src/lib/api.ts` 的 Supabase 映射、数据库迁移和服务端接口为第一事实来源；README 与旧版 `docs/prd.md` 仅作历史参考。若旧文档与代码冲突，以代码为准。例如旧版 PRD 写明“不直接生成最终视频”，但当前代码已存在视频生成、队列、轮询、历史、后台解禁和视频导出完整链路，因此本 PRD 按当前实现描述。

## 2. 产品定义

### 2.1 一句话定位

Inkplot Workshop 是一个面向 AI 短剧创作者与制作运营人员的云端生产工作台，将故事灵感转化为多集剧本、统一视觉资产、结构化分镜、AI 分镜视频和可交付的本地制作包。

### 2.2 核心价值

- 连贯生产：把灵感、剧本、资产、分镜、视频与交付放在同一项目结构内。
- 视觉一致：项目级画面风格、角色/场景美术偏好和关联资产贯穿生图与视频参考。
- 批量提效：支持 10—120 集项目设计、批量剧本、批量资产图、批量分镜与视频排队。
- 可运营：通过生产计划、任务队列、状态回收、失败恢复和生成次数控制管理长任务。
- 可交付：将剧本、资产、封面、分镜、视频与元数据导出为文件夹或 ZIP。

### 2.3 产品形态

产品为 Next.js Web 应用，当前主数据存储为 Supabase；用户通过邮箱账号登录，每个业务对象带用户归属并由行级权限隔离。AI 文本、图像和视频能力通过服务端可配置的兼容接口接入，视频另支持 Seedance 2.0 与火山素材库。

### 2.4 当前不属于产品范围的能力

- 多人项目空间、成员邀请、角色权限与实时协作；
- 剧本/分镜版本树、审阅批注、回滚与审批流；
- 视频剪辑、配乐、字幕合成、时间线合片与成片发布；
- 渠道分发、播放数据、商业化结算与用量计费；
- 原生移动端应用；
- PDF 制作包或行业标准交换格式；
- 已接入主流程的“内流控制/爽点调度”产品页面。

## 3. 目标用户与权限

### 3.1 短剧创作者 / 编剧

核心任务是从一句话灵感生成项目设计和多集大纲，逐集生成或编辑剧本，并保持人物、场景和道具设定一致。

### 3.2 制片 / 视觉内容运营

核心任务是批量补齐资产图、审查分镜提示词、关联参考资产、发起视频任务、跟踪生成状态并导出制作包。

### 3.3 系统管理员

核心任务是查看全站项目、管理视频队列、恢复卡住的任务、查看视频生成历史、给超限镜头增加一次生成机会，并清理异常记录。

### 3.4 当前权限模型

- 普通用户：邮箱登录；项目、剧集、资产、分镜、生产计划按 `user_id` 隔离。
- 管理员：独立管理入口，使用环境变量中的全局管理员密码建立 7 天 Cookie 会话。
- 当前没有项目内的 Owner/Editor/Viewer 等细粒度角色，也没有组织或团队实体。

## 4. 产品信息架构

登录后首页展示最近项目。进入项目后，左侧主导航为：

1. 总览：项目指标、工业化流水线进度、画面风格与智能封面；
2. 剧本：剧集列表、富文本编辑、项目设计、逐集/批量生成与 AI 续写；
3. 设定：角色、场景、道具的提取、编辑、出图、分类与火山素材库同步；
4. 分镜：逐集生成/编辑分镜、关联资产、视频生成与历史；
5. 生产计划：按范围和时间策略持续推进分镜与视频任务；
6. 导出：完整性预检并导出制作包；
7. 一键全流程生成：项目级跨模块流程入口。

管理后台单独提供并发队列、视频历史、全站项目与任务管理页面。

## 5. 核心用户旅程

### 5.1 标准创作旅程

灵感/梗概 → 创建项目并确定语言、画面风格与模型 → 生成 10—120 集项目设计 → 生成或编辑各集剧本 → 提取/整理角色、场景和道具 → 生成资产图片 → 生成结构化分镜 → 校正提示词和关联资产 → 生成分镜视频 → 导出制作包。

### 5.2 快速自动化旅程

创建带梗概的项目 → 点击“一键全流程生成” → 必要时生成默认 52 集设计 → 补齐缺失剧本 → 为已有设定生成图片 → 跳过已有分镜并生成缺失分镜 → 用户二次确认高成本视频生成 → 任务入队 → 状态后台回收。

### 5.3 稳态生产旅程

已有剧本 → 创建生产计划 → 选择集数范围、生产模式和触发方式 → 外部定时器触发生产 tick → 按集创建分镜规划/逐镜任务 → 可选自动排队视频 → 查看计划游标与最近任务 → 暂停、恢复或立即运行。

## 6. 功能需求

### 6.1 AUTH｜账号与访问控制

#### AUTH-01 邮箱登录与注册（已接入）

用户可使用邮箱和密码注册、登录、退出。注册支持邮箱验证回调；重复邮箱应返回明确提示。

验收口径：未登录访问首页时跳转登录页；登录成功进入项目列表；注册成功提示检查验证邮件。

#### AUTH-02 忘记与重置密码（已接入）

登录页可发送重置邮件；重置页要求密码不少于 8 位且两次输入一致。

验收口径：无有效重置会话时提示链接失效；更新成功后可用新密码登录。

#### AUTH-03 数据隔离（已接入）

项目、剧集、资产、分镜和生产计划通过 Supabase RLS 按当前用户隔离；子对象随项目或剧集删除级联清理。

### 6.2 PROJ｜项目与总览

#### PROJ-01 项目列表与生命周期（已接入）

用户可查看按更新时间倒序排列的项目，创建、编辑、进入或删除项目。删除为不可撤销操作，并级联删除剧本、设定和分镜。

#### PROJ-02 项目基础配置（已接入）

创建或编辑项目时支持：

- 必填剧名、可选梗概；
- 中文、英文、日文、韩文；
- 图像模型：Gemini 3 Pro Image 或 GPT-Image-2；
- 画面预设：海外真人剧、国内真人剧、国内 3DCG 剧；
- 人物美术和场景美术补充偏好；
- 视频模型：服务端默认、Seedance 2.0 国际版、Seedance 2.0 国内版；
- 视频画幅：9:16 或 16:9，默认 9:16；
- 火山素材库同步开关、素材组 ID 与项目名。

旧项目若只有历史美术字段，应自动推断预设；无法推断时以“国内真人剧”兜底，并在保存后写回结构化预设。

#### PROJ-03 AI 智能填充（已接入）

新建项目时，用户可输入想法、小说片段或新闻，由 AI 填充剧名、梗概、语言和美术偏好。

#### PROJ-04 项目总览（已接入）

总览应展示剧集数、资产数及角色/场景/道具分布、分镜数、已完成视频数，以及剧本、资产配图、视频三类进度。

#### PROJ-05 智能封面（已接入）

系统基于剧名、梗概、语言和最多两个优先角色生成封面标题、Slogan 与 3:4 图片提示词；一次请求四张候选图，默认选中第一张，用户可切换候选或基于当前图生成四张修改图。

验收口径：封面文案与图片地址持久化到项目；导出时使用已选封面生成项目封面和分集封面。

### 6.3 SCR｜剧集规划与剧本

#### SCR-01 剧集管理与编辑（已接入）

项目首次进入剧本页且无剧集时自动创建第 1 集。用户可添加、切换和删除剧集；正文使用富文本编辑器，停止输入 2 秒后自动保存，并展示已保存/保存中/未保存状态。

#### SCR-02 从灵感生成项目设计（已接入）

用户输入主题与目标集数，目标范围为 10—120 集，默认 52 集。系统先生成项目蓝图与初始资产，再按每批 8 集生成分集大纲。每集应包含标题、概要、开场钩子、集尾悬念和 110 秒目标时长。

重要规则：该操作会删除并重建当前项目的全部剧集与资产，界面必须持续明确提示覆盖风险。

#### SCR-03 单集与批量剧本生成（已接入）

有分集概要时可生成当前集完整剧本；也可并行生成所有带概要的剧集。生成时把项目设计和已有资产名称、类型、描述作为上下文，减少新增未定义人物或场景。

#### SCR-04 AI 续写（已接入）

系统取当前剧本文本最后 1000 个字符作为上下文，将续写内容插入编辑器并保存。

### 6.4 AST｜设定资产与图像

#### AST-01 资产分类与字段（已接入）

资产分为角色、场景、道具。每项包含名称、描述、视觉提示词、图片、关联剧集、是否核心主角、状态和供应商同步信息。用户可新建、编辑、删除、搜索，并按剧集筛选。

#### AST-02 图片上传与生成（已接入）

用户可上传不超过 50MB 的图片、填写外部图片 URL，或基于视觉提示词和项目画面风格生成图片。项目默认图像模型应被封面、资产页和一键流程统一使用。

#### AST-03 从剧本自动提取（已接入）

系统按集分析全部剧本，提取角色、场景和道具；同一次提取中按名称去重并累积关联剧集，已存在的同名资产不重复导入。用户可在预览中勾选、单项/批量生成图片后再导入。

#### AST-04 批量补图（已接入）

对有视觉提示词但缺少图片的资产执行批量生图，展示完成数和总数；单项失败不阻断剩余资产。

#### AST-05 火山素材库同步（已接入）

开启项目同步后，可查看可同步、Active、Processing、Failed、未同步和最后同步时间；支持刷新状态、仅重试未同步/失败项、重新提交 Processing 项以及清空本地同步记录后完全重传。

业务约束：Seedance 2.0 使用素材库引用时，关联素材需进入 Active；国际版可优先使用源 URL。图片改变后，本地旧同步记录应清空。

### 6.5 STB｜分镜脚本

#### STB-01 AI 两阶段分镜生成（已接入）

分镜生成先执行“镜头规划”，再逐镜生成详细信息。长剧本会先分段规划再合并；逐镜生成带入前一镜和后一镜规划以增强连续性。

生成字段至少包括：镜头序号、画面描述、对白/旁白、运镜、景别、时长、场景标签、角色动作、情绪、光影氛围、音效、视频提示词、出场角色和关联资产。

业务规则：

- 单集目标时长固定为 110 秒；
- 建议镜头数 8—13；
- 单镜头时长限制 4—15 秒，默认 14 秒；
- 重新生成当前集会先删除该集已有分镜；
- 批量生成前必须确认覆盖风险。

#### STB-02 分镜人工编辑（已接入）

用户可新增、删除、保存和拖拽排序镜头；可调整分镜字段、时长、敏感度降低等级与关联资产；可复制某镜头的资产集合供其他镜头使用。

#### STB-03 敏感度降低（已接入）

项目级可配置敏感词规避规则；单镜头可设置无、轻度、中度、强四档，并通过 AI 生成降敏前后对比后保存结果。

#### STB-04 单镜头辅助操作（已接入）

支持复制分镜文本、将分镜卡片导出为图片、查看详细编辑页、预览已生成视频和查看视频历史。

### 6.6 VID｜视频生成与状态管理

#### VID-01 视频任务发起（已接入）

用户可对单镜头生成视频，也可为当前剧集或全项目批量发起。请求包含视频提示词、4—15 秒时长、画幅、声音开关、镜头参考图与已关联资产图片。

#### VID-02 双视频通道（已接入）

- 默认视频模型：使用服务端通用 AI 视频接口；
- Seedance 2.0：支持国际版和国内版，固定 480p，可优先使用 Active 的火山素材 ID 或源 URL。

#### VID-03 队列与状态（已接入）

状态包括 pending、queued、processing、completed、failed。前端可取消尚未提交供应商的排队任务；后台每分钟同步视频状态，并将完成 URL 或错误信息写回镜头。

#### VID-04 视频历史与次数控制（已接入）

每个镜头保留最多 30 条生成历史。失败记录不占用次数；默认允许 3 次有效生成，耗尽后前台锁定。管理员可为指定镜头增加 1 次机会，并记录解禁次数、时间和管理员标识。

### 6.7 PLN｜生产计划

#### PLN-01 生产计划创建（已接入）

用户可指定计划名称、集数起止范围和以下生产模式：

- 分镜后生成视频；
- 只生成分镜；
- 只排队视频。

触发方式支持手动、指定时间一次、每天固定时间、每隔 N 分钟。可选择跳过已有分镜、自动排队视频，以及创建后立即执行首轮。

#### PLN-02 稳态推进与任务拆分（已接入）

生产计划按集推进，通过分镜分段规划、计划收敛、逐镜生成、整集视频入队四类任务拆分工作。计划维护下一集游标、上下次执行时间和 active/paused/completed/failed 状态；任务默认最大尝试 3 次。

#### PLN-03 计划与任务观测（已接入）

页面展示启用计划数、pending/running/failed 任务、最近推进、计划集数进度和最近 100 条任务；用户可立即运行、暂停或恢复计划。

### 6.8 EXP｜导出交付

#### EXP-01 导出预检（已接入）

导出前汇总项目封面、分集数、资产缺图数、分镜数和缺视频数。资源缺失不阻断导出，但必须明确提示缺失项。

#### EXP-02 文件夹与 ZIP（已接入）

Chrome/Edge 等支持 File System Access API 的浏览器可选择本地目录并流式写入；其他浏览器回退为 JSZip 下载。

#### EXP-03 制作包结构（已接入）

导出内容包括：

- 根目录项目封面、README 与 `meta.json`；
- `covers/` 分集封面；
- `scripts/` 每集剧本文件；
- `assets/characters|locations|props/` 设定图；
- `storyboards/` 每集分镜 Markdown 与参考图；
- `videos/episode_N/` 按集归档的已完成视频。

### 6.9 OPS｜管理后台

#### OPS-01 队列管理与恢复（已接入）

管理员可查看等待、运行和全局视频队列，移除单项、清空集合、向供应商查询真实状态并恢复单个或批量任务；页面每 5 秒刷新一次。

#### OPS-02 视频历史统计（已接入）

管理员可按项目、剧集、镜头逐级查看分镜数、视频任务、历史覆盖、生成次数、重复生成和状态分布，并对锁定镜头解禁一次。

#### OPS-03 全站项目与任务（已接入但入口不完整）

管理员可查看并级联删除全站项目；任务管理页可修改任务状态或删除任务，但当前管理导航没有“任务管理”入口，只能直接访问路由。

## 7. 一键全流程生成

### 7.1 执行阶段

1. 获取项目；若既无概要也无正文，则基于项目梗概尝试生成默认 52 集设计和初始资产；
2. 为有概要但正文为空的剧集生成剧本；
3. 跳过二次剧本资产提取，直接使用项目设计阶段的已有资产；
4. 为缺图且有视觉提示词的资产生成图片；
5. 对没有分镜的有效剧集按每批 2 集生成分镜；
6. 二次确认后，为所有未完成、未排队、未处理的镜头发起视频任务。

### 7.2 交互要求

- 展示 0—100% 进度和逐步日志；
- 单项失败尽可能继续处理剩余项；
- 视频阶段因成本高必须再次确认；
- 运行中不可关闭弹窗；完成后刷新页面。

### 7.3 当前行为差异

“创意生成”页面按 8 集一批生成 10—120 集大纲，而一键流程的空项目分支直接期待蓝图接口返回 52 集 `series_outline`；两条路径对同一能力的接口契约不一致，需要统一。

## 8. 关键业务规则

| 规则编号 | 当前规则 | 说明 |
|---|---|---|
| BR-01 | 项目数据归当前登录用户所有 | 由 `user_id` 与 RLS 实现 |
| BR-02 | 项目设计支持 10—120 集，默认 52 集 | 生成后覆盖当前剧集和资产 |
| BR-03 | 单集目标时长为 110 秒 | 当前最小值与最大值均为 110 |
| BR-04 | 单镜头 4—15 秒，默认 14 秒 | 所有保存与生成入口均归一化 |
| BR-05 | 单集分镜建议 8—13 镜 | 分镜规划约束 |
| BR-06 | 默认视频画幅 9:16 | 项目可改为 16:9 |
| BR-07 | 视频有效生成默认最多 3 次 | 失败不计数，管理员可增配 |
| BR-08 | 单镜头最多保留 30 条视频历史 | 超出后保留最近记录 |
| BR-09 | 图片上传上限 50MB | 大于 20MB 使用分片上传 |
| BR-10 | 核心主角用于封面优先参考 | 当前 UI 未限制“最多 2 个” |
| BR-11 | 资产状态定义 draft/locked | 当前 UI 未提供锁定操作，也未阻止 locked 编辑 |
| BR-12 | Seedance 2.0 固定 480p | 国际版/国内版可选 |
| BR-13 | 生产任务默认最大尝试 3 次 | 计划/任务表记录 attempts |
| BR-14 | 导出允许资源不完整 | 缺失资源只提示，不阻断 |

## 9. 数据模型

| 实体 | 关键字段 | 关系与用途 |
|---|---|---|
| Profile | id、email、full_name、avatar_url | 一对一关联认证用户 |

## 11. 非功能需求

### 11.1 安全与隐私

- 所有普通用户业务接口应校验 Supabase 用户身份，并依赖 RLS 做第二层隔离。
- 所有 cron 环境必须强制配置 `CRON_SECRET`；缺失时不得开放执行。
- 管理员会话应使用不可逆验证和签名令牌，不应把环境变量原始密码直接作为 Cookie 值。
- 所有 AI 接口均应验证用户身份、限制请求大小和频率，并记录可审计的用户与项目上下文。
- 导出前不应把密钥、供应商原始响应或内部队列标识写入用户制作包。

### 11.2 性能与可靠性

- 长任务不得依赖单个浏览器会话长期存活；视频与生产任务应可由后台继续推进。
- 分集、资产、分镜批量任务应使用可配置并发和背压，单项失败不阻断整批。
- 视频队列应具备幂等键、超时回收、状态重试与异常恢复。
- 生产 tick 单次运行上限 270 秒，默认每次处理少量计划/任务，避免 serverless 超时。

### 11.3 可用性与可访问性

- 高成本、覆盖性、不可撤销操作必须二次确认并显示影响范围。
- 批量操作必须持续显示进度、已完成/失败数与可恢复状态。
- 桌面端为主要生产形态；当前页面具备一定响应式布局，但 400px 固定分镜资产栏等区域仍需移动端专项验收。
- 图像、视频和表单控件应补齐键盘操作、焦点状态、替代文本和错误关联。

### 11.4 可观测性

- 任务应记录状态、尝试次数、供应商任务 ID、错误、开始/结束时间和生成历史。
- 产品层应补充按用户、项目、模型统计的成功率、耗时、重试与成本。

## 13. 现状问题与风险

### 13.1 P0｜发布与安全门槛

- 三个 AI 路由（封面设计、电影滤镜适配、内流调度）未在路由内部校验用户；当前中间件只刷新会话，不承担 API 授权。
- 两个 cron 接口仅在 `CRON_SECRET` 已配置时验证 Bearer；若变量缺失，接口可被直接调用。
- 管理 Cookie 保存管理员原始密码值，缺少签名、轮换和独立会话令牌。
- `npm run lint` 当前有 28 个错误、17 个警告，不满足持续集成质量门槛。

### 13.2 P0｜关键流程一致性

- 一键全流程的视频画幅硬编码为 9:16，可能忽略项目配置的 16:9。
- 生产计划要求外部每分钟触发 `/api/cron/production`，但 `vercel.json` 只配置了视频状态同步 cron。
- 内流控制字段虽在新建项目对象中赋值，但 `api.projects.create` 和读取映射未持久化/恢复这些字段。

### 13.3 P1｜数据与业务规则

- `api.update` 对部分字段使用真值判断，空字符串不能可靠用于清空梗概、正文、提示词或图片地址。
- 核心主角注释写“最多 2 个”，UI 和数据库没有数量约束。
- 资产 `locked` 状态没有操作入口，也没有阻止后续编辑或重新生成。
- 剧本文正存为 HTML，导出时直接写入 `.md` 文件，文件扩展名与内容语义不完全一致。
- 类型/数据库包含导演意图、转场、内流等字段，但主 API 映射缺失，容易造成“看似保存、实际丢失”。

### 13.4 P1｜成本与规模

- 一键流程默认 52 集，批量视频可一次对大量镜头发起；当前没有用户配额、成本预估、预算上限或消费确认明细。
- 部分批量入口在浏览器端创建 50 或 2000 个并发 Promise，实际背压依赖后端队列，前端仍有内存、超时和请求风暴风险。
- 失败恢复主要面向管理员，普通用户缺少清晰的按集重试和失败原因聚合。

### 13.5 P2｜工程与体验

- 生产构建在本次环境中因无法下载 Google Geist 字体而失败，说明构建依赖外网字体；应改为本地字体或在构建基础设施中保证可访问性。
- 现有测试文件没有可直接运行的项目测试脚本；直接 Node 测试时路径别名无法解析，仅视频 payload 的 4 个独立测试通过。
- 部分页面存在固定宽度、原生 `alert/confirm`、错误仅写控制台等体验不一致问题。

## 14. 建议目标与指标（待业务确认）

以下为建议，不是当前代码事实。

### 14.1 北极星指标

每周成功导出的“完整项目包”数量。完整定义建议为：至少 1 集非空剧本、关键资产有图、至少 1 集有分镜，且导出成功。

### 14.2 漏斗指标

- 项目创建 → 生成项目设计转化率；
- 项目设计 → 至少一集完整剧本转化率；
- 剧本 → 至少一集分镜转化率；
- 分镜 → 视频任务成功完成率；
- 完成视频 → 制作包导出率。

### 14.3 质量与效率指标

- 文本/生图/分镜/视频接口成功率与 P50/P95 耗时；
- 单集从大纲到分镜的人工操作时长；
- 视频任务首次成功率、平均有效尝试次数、锁定率；
- 资产关联缺失率、导出缺图率、导出缺视频率；
- 队列超时与管理员人工恢复率。

## 16. 验收场景

### 场景 A｜从零创建 10 集项目

用户注册并新建中文、国内真人剧、9:16 项目，输入灵感生成 10 集项目设计；系统创建 10 集结构化概要和初始资产，用户批量生成剧本、资产图、分镜，数据刷新后仍存在。

### 场景 B｜从现有剧本提取并关联资产

用户在多集剧本中执行自动提取；同名角色只出现一次但关联多集。用户选择部分资产并生成图片，导入后可按集筛选，并能在分镜中选择该资产。

### 场景 C｜视频生成与次数控制

用户为带视频提示词和关联图片的镜头发起任务，状态依次进入 queued/processing/completed 或 failed；完成后可播放并出现在历史中。完成 3 次有效生成后前台锁定，管理员解禁后可再生成 1 次。

### 场景 D｜生产计划

用户创建第 1—10 集“分镜后生成视频”的间隔计划，选择跳过已有分镜并立即运行；外部 cron 多次触发后计划游标单调推进，重复 tick 不重复创建同一集有效任务，暂停后不再推进。

### 场景 E｜不完整项目导出

项目缺少封面、部分资产图和部分视频时，导出总览准确显示缺失数；用户确认后仍能获得包含现有剧本、分镜、媒体、README 与 `meta.json` 的文件夹或 ZIP。

### 场景 F｜用户隔离

用户 A 无法通过页面、客户端查询或服务端接口读取、修改、删除用户 B 的项目及其子对象。
